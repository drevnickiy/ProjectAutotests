> **Суть проекта**: Автоматизация E2E-тестирования и Data-Driven наполнения (сидинга) ERP/APS системы **Creatio 8.x Freedom UI** (производственный цикл косметики/бытовой химии: варка массы в реакторах, фасовка, упаковка, BOM-спецификации, расчет партий).

### 🚀 Стек, окружение и команды
- **Стек**: TypeScript, Playwright Test (`workers: 1`, `storageState`), Node.js.
- **Окружения (`.env`)**: `main` (`xlab-analyst-main`), `main2` (`xlab-analyst-main2`), `preprod` (`xlab-preprod`). Логика переключения серверов и сессий: [src/config/environment.ts](file:///Users/bogdansunday/Desktop/Xlab2/src/config/environment.ts).
- **Команды запуска**:
  - Тест: `npx playwright test e2e/functional/<name>.spec.ts`
  - Сид: `npx playwright test scripts/seeds/<name>.ts` (или вся цепочка: `npx playwright test --project=seeds`)
  - Генерация отчёта вручную: `npm run report:generate` -> `custom_report.html`

# Правила и регламент выполнения тестов в проекте Xlab

## 1. Автоматическая генерация и отправка отчетов на почту
- Все прогоны Playwright авто-тестов автоматически вызывают `globalTeardown: './src/utils/generateAndSendReport.ts'`.
- После прогона формируется интерактивный HTML-дашборд `custom_report.html` с изумрудной подсветкой статусов, фото-галереей скриншотов каждого шага и фильтрацией.
- При наличии настроек SMTP в `.env` (`SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `EMAIL_TO`) отчет автоматически отправляется в виде HTML пиьсма и вложения на указанный e-mail.

## 2. Изоляция сессии (storageState)
- Однократная авторизация выполняется в `e2e/auth.setup.ts` и сохраняется в `storageState.json`.
- Последовательное выполнение (`workers: 1`, `fullyParallel: false`) обеспечивает 100% стабильность работы с сервером Creatio без обрывов HTTP/2 сессий.

## 3. Регламент исправления багов и взаимодействия
- При исправлении ошибок UI или фиче-запросов НЕ запускать браузерный субагент для самостоятельного тестирования без согласия пользователя.
- НЕ перезапускать тесты (npx playwright test) без явного указания/команды пользователя.
- Взаимодействие: сначала сделать исправление, затем сказать пользователю: «Я пофиксил, проверь пожалуйста!», давая пользователю возможность самому протестировать решение.
## 4. Регламент предоставления отчета по тестам в чате
- Всегда выводить детальный отчёт в чат по результатам прогона тестов.
- Отчёт обязателен к наглядному оформлению: включать общую статистику (Passed / Failed), список упавших тестов со списком ВСЕХ ненайденных/отсутствующих полей и ссылками на соответствующие скриншоты/фотографий ошибок (BUG / failure screenshot), а также ссылку на `custom_report.html`.
- В `test-history.json` хранится история текущего + 2 предыдущих прогонов для вкладки «📈 Статистика» в дашборде.

## 6. Принцип Data-Driven сидинга (Разделение данных и кода)
- **Строгое правило**: При необходимости изменить или добавить тестовые данные для наполнения Creatio (продукты, оборудование, техкарты, материалы) — **НЕ модифицировать TypeScript-код скриптов в `scripts/seeds/`**.
- Все данные подаются исключительно через редактирование соответствующих JSON-файлов в `scripts/data/` (`equipment.json`, `semi_finished_products.json`, `finished_products.json`, `raw_materials.json`, `semi_finished_routings.json`, `finished_routings.json`, `semi_finished_materials.json`, `finished_materials.json`).
- Код скриптов `scripts/seeds/*.ts` меняется ТОЛЬКО в случае изменения логики работы UI Creatio или фикса багов селекторов.

## 8. Золотой стандарт заполнения Технологических карт (ТК для ГП и НФ)
- **Детальная спецификация**: закреплена в скілі `.agents/skills/creatio-routing-expert/SKILL.md` и `.agents/skills/codebase-map/SKILL.md` (Раздел 6).
- **Профессиональный формат названий ТК**:
  - Для ГП: `ТК-ГП | <Назва продукту> <Об'єм>` (напр. `ТК-ГП | Шампунь Hydrasence 400 мл`).
  - Для НФ: `ТК-НФ | Варка <назва напівфабрикату>` (напр. `ТК-НФ | Варка шампуню Hydrasence`).
- **Лимит названий**: Все названия этапов и задач строго **до 50 символов**.
- **ТК для Готовой продукции (ГП)**:
  - **3 Этапа**: `Санітарна обробка та дезінфекція`, `Фасування у флакони <об'єм> мл`, `Етикетування з датером та пакування`.
  - **4 Задачи (СТРОГО БЕЗ ВКЯ!)**:
    1. `Миття, дезінфекція обладнання та інвентарю` (Тип: `Фасування`, `Сервісне завдання`, 1.0 год / 60 хв, `Ігнорувати кількість = TRUE`).
    2. `Розлив у флакони <об'єм> мл та укупорка` (Тип: `Фасування`, `Виробниче завдання`, нормируется на 1 шт, `Ігнорувати кількість = FALSE`).
    3. `Етикетування та маркування датером` (Тип: `Маркування та пакування`, `Виробниче завдання`, нормируется на 1 шт, `Ігнорувати кількість = FALSE`).
    4. `Групове пакування у гофрокороби` (Тип: `Маркування та пакування`, `Виробниче завдання`, 0.05 хв = 0.0008 год на 1 шт, `Ігнорувати кількість = FALSE`).
  - ⚠️ **СТРОГОЕ ПРАВИЛО**: В технологические карты Готовой продукции (ТК-ГП) этап/задача **ВКЯ (контроль качества) НЕ ДОБАВЛЯЕТСЯ**! ВКЯ проводится только на этапе полуфабрикатов (НФ).
- **ТК для Полуфабрикатов (НФ — Синтез/Варка)**:
  - Этапы: `фаза А`, `фаза Б`, `фаза В`, `фаза фініш + ВКЯ`.
  - Оборудование: `Реактори`.
  - Задачи: **100% задач имеют `Ігнорувати кількість = TRUE`** (фиксированное время технологического цикла варки реактора).

## 9. Правило прив'язки Напівфабрикатів (НФ) до Реакторів (Вкладка «Вихід»)
- **Суворе правило**: При додаванні та конфігурації обладнання з типом `Реактори` (`GenEquipment` з типом `Реактори`) **ОБОВ'ЯЗКОВО** додавати створені напівфабрикати (**НФ**) у деталь/вкладку **«Вихід»** (`GenEquipmentProducts`).
- **Чому це критично**: Алгоритм розрахунку та авто-планування замовлень Creatio (APS / «Запланувати виробництво») підбирає обладнання для етапу варіння НФ виключно через перевірку наявності відповідного НФ у вкладці «Вихід» реактора. Якщо НФ там не вказано — планувальник не зможе призначити реактор на замовлення!
- **Параметри прив'язки у «Вихід»**:
  - `GenProductId`: Guid напівфабрикату (НФ).
  - `GenProductUnitId`: Базова одиниця виміру НФ (`ProductUnit` — кілограм).
  - `GenOutput`: Продуктивність (кг/год), яка розраховується як `Об'єм реактора (кг) / Час повного циклу (год)` (напр. 1000 кг / 4.0 год = 250 кг/год; 1000 кг / 3.5 год = 285.714 кг/год).
  - ⚠️ **СТРОГОЕ ПРАВИЛО**: У вкладку «Вихід» реакторів **НІКОЛИ НЕ додається Готова продукція (ГП)** — реактор здійснює синтез/варіння виключно напівфабрикату (маси).

## 10. Одиниці виміру для Продукції (ГП та НФ)
- **Суворе правило**: Для всіх продуктів (як для **НФ**, так і для **ГП**) в системі Creatio обов'язково повинна бути додана одиниця виміру **`кілограм`**, і вона **ОБОВ'ЯЗКОВО повинна бути встановлена як «Базова одиниця» (`IsBase = true`)**.
- **Чому це критично**: Рецептури (BOM / Матеріали продукту), норми витрат сировини, потужності реакторів та розрахунки виробничих партій у Creatio базуються на вазі (кг). Якщо базова одиниця не кілограм, формули балансу та списання сировини в техкартах розраховуються некоректно.
- **Штуки (`штук`)**: Одиниця виміру `штук` додається у деталь **«Одиниці виміру»** продукту як вторинна (пакувальна/товарна) одиниця (`IsBase = false`) з коефіцієнтом перерахунку базових одиниць (`NumberOfBaseUnits`, наприклад для флакона 400 мл — 2.353–2.5 шт/кг; для 150 мл — 6.667 шт/кг).
